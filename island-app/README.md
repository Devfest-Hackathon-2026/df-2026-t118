# 島アプリ — ターン3の実装

デザインボード `島アプリ ボード.dc.html` のターン3「ブランドの方向性 — ぷっくりツヤの3D × 細い見出し × レトロなUIパネル」を、
フレームワークなしの HTML + CSS + JS で実装したもの。

ボードは Claude Design のキャンバス形式（`<x-dc>` テンプレート、`{{ }}` 補間、`<dc-import>`、`DCLogic`）で、
`support.js` のランタイムがないと動かない。ここではそのランタイムを外し、3D は `island.js` を直接使っている。

## 実行

このフォルダで:

```bash
python3 -m http.server 4412
```

`http://localhost:4412` を開く。ハッシュで画面を直接指定できる（`#sheet` `#s2` `#s3` `#s4` `#s6`）。

## ボードとの対応

| ボード | 画面 | 地の色 |
|---|---|---|
| 3a ブランドシート | `#sheet` | Sky |
| 3b S2 島 | `#s2` | Sky |
| 3c S3 保存 | `#s3` | Bubble |
| 3d S4 今日の一歩 | `#s4` | Butter |
| 3e S6 建った | `#s6` | Paper |

## ボードから変えたところ

- **3D はスナップショットではなくライブ**。ボードは `Island.snapshot()` で焼いた PNG を貼っていたが、
  ここでは `Island.mount()` でそのまま描画する。ドラッグで回り、ピンチ／ホイールで寄れて、カードをタップすると
  ぽこがそのカードの話をする。`mount()` は `opts.rot` を見ない（`snapshot()` 専用）ので初期角はライブ側の既定。
- **WebGL は1画面につき1つ**。見えている画面の島だけマウントし、画面を移ると破棄する。
- **4画面が1本の流れになっている**。S2 の `+` → S3 →（候補を選ぶ）→ S4 →「やってみる」→ S6。
  選んだ候補が S4 の一歩・所要時間・ぽこのことば、S6 の建物名まで決める。
- **キーは実際に沈む**。`:active` で 2px 下がり影が消える。ボードの静止画では出せなかった挙動。
- **実機幅（460px 以下）ではガワを外して全面表示**にする。

## ファイル

| パス | 内容 |
|---|---|
| `index.html` | 5画面のマークアップ |
| `styles.css` | 3a のブランドトークン（色・字組み・パネル・キー）と各画面の座標 |
| `app.js` | 画面遷移、島のマウント、ステッカー生成、Avatar、S3 の候補選択 |
| `vendor/island.js` | デザインプロジェクトからそのままコピー（three.js r128 が必要） |

`Avatar.dc.html` のぽこ／ともり／ふみは `styles.css` の `.avatar--*` に移植した。
`data-avatar` と `data-size` を置けば `app.js` が中身を組む。

## 補ったところ

S3 の候補3つのうち、ボードが S4・S6 まで指定しているのは候補1（`PARAの4つのフォルダを作る` → `書斎`）だけ。
候補2・3 の一歩と建物名は、流れを同じ文法で動かすために `app.js` の `CHOICES` で補っている。
