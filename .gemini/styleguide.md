# レビュー方針（Gemini Code Assist）

- レビューは日本語で行う
- 指摘には、問題となる理由と修正方針を添える
- 優先順位
  1. 機密情報の混入（API キー、認証情報）
  2. 動作不良やデータ破壊につながるバグ
  3. セキュリティ上の問題（外部入力を検証せず利用するなど）
  4. 想定外の課金につながる実装（ループ内の API 呼び出しなど）
  5. 保守性（責務の分離、関数の長さ、命名）
- スタイルの好みに関する指摘は最小限にする
- `docs/architecture.md` および `docs/decisions/` の ADR と矛盾する変更は指摘する
