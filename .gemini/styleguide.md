# レビュー方針（Gemini Code Assist 向け）

このリポジトリは、初心者を含むチームのハッカソン作品です。

## レビューのしかた

- **日本語で**レビューすること
- 指摘には「なぜ問題か」と「どう直すか」を、初心者にもわかる言葉で添えること
- 専門用語には一言説明をつけること
- 細かいスタイルの好みより、次を優先して指摘すること
  1. APIキーなど機密情報の混入
  2. 動かなくなる・データが壊れるバグ
  3. セキュリティ上の問題（外部入力をそのまま使う、など）
  4. 課金が想定外に増えそうな処理（ループ内でのAPI呼び出し、など）
  5. 読みにくさ（コメント不足、長すぎる関数）
- 良い点があれば1つ褒めること

## プロジェクトのルール

- ルール全体は `AGENTS.md`、設計は `docs/architecture.md`、技術選定の理由は `docs/decisions/` にあります
- `docs/architecture.md` や ADR と矛盾する変更があれば指摘すること
