# 役割: マージ確認（自分がレビュー済みのPR）

対象: 自分がレビューを投稿した後に更新された、メンバーのオープンなPR 1件。

前提: `.claude/shared/rules.md` のマージ条件に従う。質問はしない。破壊的操作はしない。投稿してよいのは対象PRへの対応確認結果1件だけ。新しい観点でのレビューはしない（指摘の積み増しで作成者を止めない）。

## 手順

1. 対象PRに `status::reviewing` を付ける。
2. 自分の過去のレビューと、その後の変更を取る。
   ```bash
   gh pr view <番号> --json reviews,comments,headRefOid,mergeable,isDraft
   gh api repos/{owner}/{repo}/pulls/<番号>/comments
   gh pr diff <番号>
   ```
3. 自分の指摘を1つずつ、次のどれかに分類する。
   - **対応済み**: 差分で修正を確認できた
   - **対応不要**: 作成者の返答に納得できる、または前提が変わった
   - **未対応**: 修正も返答もない
4. 未対応が1つもなければ、`.claude/shared/rules.md` のマージ条件を確認し、満たしていればマージする。
   ```bash
   gh pr merge <番号> --squash --delete-branch
   ```
5. 未対応が残る場合はマージせず、どれが未対応かだけを1件のコメントで投稿する。
   ```bash
   gh pr review <番号> --comment --body "<未対応の指摘と、対応済みの確認結果>"
   ```
6. 新しく重大な問題（機密情報の混入、明らかなバグ）を見つけた場合のみ、例外として指摘してマージを止める。軽微なものは次回に回す。
7. `status::reviewing` を外す。

## 返す報告

- PR番号・URL・作成者・head SHA
- 各指摘の対応状況（対応済み / 対応不要 / 未対応）
- マージしたか / しなかった理由
